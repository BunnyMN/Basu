# Үүрэг, цэс бол Basu-гийн өгөгдөл: dashboard-аас үүсгэж, хуудас оноож, байрлуулна

ADR 0003-т эрхийг нэг хүснэгт болгосон ч үүрэг нь кодод тогтсон дөрөв, дөрвөн
үг, цэс нь кодод бичигдсэн жагсаалт байв. Эзэмшигч үүнийг хүлээж аваагүй:
«би өөрөө role бүртгээд, түүн дээрээ өөрөө хуудас нэмж хасдаг болмоор байна»,
«merchant-даа эрх оноож өгөх», «left navigation bar-аа module, menu гэх мэт
бүтэцтэй». Үүрэг бүр release шаарддаг байх нь бизнесийн шийдвэрийг хөгжүүлэгчийн
ажил болгож байв.

Шийдвэр: **эрх** кодод үлдэнэ — код зөвхөн өөрийн хийж чадах зүйлийг л хийнэ.
Хуудас бүр нэг харах эрхтэй (`desk.guests`), дээрх үйлдэл бүр нэг эрхтэй
(`desk.guests:close`); бүгд `src/platform/access/catalog.ts`-д. Бусад нь
**өгөгдөл**, `access` schema-д, Basu-гийн ширээнээс засагдана:

- **Үүрэг** (`access.role`) — ширээний (`desk`) эсвэл байгууллагын (`org`).
  «Үүрэг, эрх» хуудсанд нэр, тайлбар өгч үүсгээд, модуль → хуудас → үйлдэл
  модноос чагтална. Үйлдэл чагталбал хуудас нь дагаж чагтлагдана.
- **Merchant-ийн үүрэг** (`access.org_role`) — үүрэг «бүх байгууллагад»
  нээлттэй, эсвэл зөвхөн сонгосон байгууллагад. «Байгууллагууд → Үүрэг, эрх»
  хуудсанд байгууллага бүрт нээх үүргээ, тэнд ажилладаг хүн бүрийн үүргийг
  (эзнийг ч) Basu оноож болно.
- **Цэс** (`access.module`, `access.page`) — «Цэс» хуудсанд модулийн нэр,
  дүрс, дараалал; хуудас бүрийн нэр, дүрс, аль модульд, ямар дараалалд,
  харагдах эсэх; шинэ модуль, холбоос (Basu-гийн зам эсвэл https) нэмнэ.
  Кодын хуудас мөргүй бол кодын анх тавьсан газраа сууна.

Зүүн цэс **Модуль → Цэс** мод: дээд хэсгийн хуудсууд, дараа модуль бүр
дүрс, нэр, эвхэх сумтай мөр, доор нь хуудсууд нь шугам дээр. Хүн бүрийн цэс
= Basu-гийн байрлуулсан модуль, хуудсууд ∩ түүний үүргийн харах эрх.

Хамгаалалт:

- Ширээний **админ** үүрэг түгжээтэй — бүгдийг нээнэ, засагдахгүй, устахгүй.
  Ингэснээр Basu өөрийгөө хэзээ ч түгжихгүй.
- Анхны үүргүүд (ops, санхүү, зөвхөн харах, эзэн, менежер, ажилтан, нягтлан)
  засагдана, устахгүй. Хэн нэгэн эзэмшиж, хүсэж, урьсан үүрэг устахгүй.
- Хэн ч өөрт байхгүй эрхийг үүрэгт бичихгүй, өөрөөсөө их эрхтэй үүргийг
  хэнд ч оноохгүй (админаас бусад). Байгууллагад «эзэн» болон ажилтан
  удирдах эрхтэй үүргийг зөвхөн `org.team:heads`-тэй хүн ононо; байгууллага
  хэзээ ч эзэнгүй үлдэхгүй.
- Байгууллагын төрөл хуудсыг хязгаарлана хэвээр: идэшний хуудас зөвхөн
  нийлүүлэгчид, хоолны хуудас зөвхөн ресторанд — үүрэг юу ч гэсэн.

## Хаясан хувилбарууд

- **Үүргийг кодод үлдээх** (ADR 0003) — эзэмшигч өөрөө удирдахыг шаардсан;
  бизнесийн шийдвэр release-ээс хамаарах ёсгүй.
- **Эрхийг ч өгөгдөл болгох** — кодод route байхгүй эрх бол худал: чагтлаад
  юу ч нээхгүй. Эрх кодоос, түүнийг хэнд өгөх нь өгөгдлөөс.
- **Хуудас бүрт «харах/нэмэх/засах/устгах» дөрвөн баган** — Basu-гийн
  хуудсуудын үйлдэл ийм нэгэн хэвийн биш (цуцлах, батлах, данс солих);
  хуудас бүрийн жинхэнэ үйлдлүүдийг нэрээр нь харуулах нь ойлгомжтой.
- **Merchant-ийн эзэн өөрөө үүрэг үүсгэх** — одоохондоо Basu төвлөрсөн
  хяналт хүснэ; эзэн нь Basu-гийн нээсэн үүргүүдээс ононо.

## Үр дагавар

- Шинэ хуудас = каталогт нэг мөр (хуудас, үйлдлүүд) + route-д эрх шаардах +
  хуудсыг зурдаг код. Түүнээс хойш хэнд харуулах, хаана байрлуулах нь бүгд
  dashboard-аас.
- Анхны үүргүүдийг сервер эхлэхдээ дутуу бол бичнэ, Basu-гийн өөрчилснийг
  хэзээ ч дарж бичихгүй (миграц 033).
- Гишүүний үүрэг хуучин текст баганадаа — одоо `access.role`-ийн түлхүүр.
