## Ажиллуулах

```bash
createdb basu_dev basu_test
cp .env.example .env       # DATABASE_URL-ээ шалгана уу
npm install

npm run verify             # бүх зүйлийг нэг командаар шалгана
npm run dev                # миграц + демо өгөгдөл + сервер
```

`npm run dev`-ийн дараа:

| | |
|---|---|
| Basu нүүр | http://localhost:3000/ |
| Хоол (dine-in) | http://localhost:3000/dine |
| Тогооч | http://localhost:3000/kds |
| iOS апп | `npm run ios` (симулятор) |

Docker хэрэггүй — локал Postgres 16 хангалттай. Тест `basu_test` санг ашиглаж,
схемийг ажиллуулах бүрд шинээр босгодог.

### Демо цаг

Үдийн үйлчилгээ 11:30–14:00-д явагддаг, галлах ба суух хоёрын хооронд 15 минут
байдаг. Тиймээс бүтээгдэхүүнийг өдрийн 4 цагт үзүүлэх, эсвэл бодит цагаар
эхнээс дуустал харах боломжгүй. Хөгжүүлэлтэд цаг бол **удирдлага**:

```
11:40 захиалга │ 12:14 arm │ 12:21 гал │ +1 мин │ +5 мин │ Scheduler
```

Хоолны дэлгэцийн дээд талын зурвасаас цагийг үсэргэж, scheduler-ийг гараар
гүйлгэнэ. Зурвас **зөвхөн хоолны апп дотор** байдаг — launcher, түрийвч,
мэдэгдэл, профайл дөрөв нь shell бөгөөд дизайны дагуу зурагдана. Production-д
`src/entry/*` нь `systemClock` ашигладаг тул зурвас огт гарахгүй.

Launcher-ыг нэг иконоор биш, **өсөлтөөр нь** шалгана. Дизайн 1 / 4 / 9 иконтой
байдлыг зааж өгсөн тул debug build дээр гурвуулааг харж болно:

```bash
SIMCTL_CHILD_BASU_APPS=9 xcrun simctl launch booted mn.basu.app
```

Есөн икон дээр хоёр редакцийн бүлэг (`ӨДӨР ТУТАМ` / `БУСАД`) ба шүүлтүүр гарч
ирнэ. Хавтас байхгүй, сүүлд хэрэглэснээр эрэмбэлэхгүй — товчоор сурч болохгүй
grid бол grid биш. Сүүлийн үеийн зүйл ИДЭВХТЭЙ хэсэгт байна.

### Платформ ба vertical-ийн зааг

Модуль бүр өөрийн Postgres schema-тай (`identity`, `ledger`, `notify`, `dine`)
бөгөөд өөр модулийн хүснэгтийг нэрлэж чадахгүй — `search_path` нь `public`-д
тогтоосон тул мартсан query нь ажиллахын оронд шууд унана.

| Модуль | Schema | Гадагш харагдах хаалга |
|---|---|---|
| identity | `identity.*` | `src/platform/identity/index.ts` |
| ledger | `ledger.*` | `src/platform/ledger/index.ts` |
| notify | `notify.*` | `src/platform/notify/index.ts` |
| хоол (vertical) | `dine.*` | — |

Schema хооронд гадаад түлхүүр байхгүй: `dine.dining_order.guest_id` нь
`identity.guest.id`-г заадаг ч FK биш. Тэр гагнаас нь байвал модулийг өөрийн
сервис болгож салгах өдөр production дээр яаралтай тайрах шаардлагатай болно.

Заагийг `src/test/boundaries.test.ts` барина. Унавал жагсаалтыг тэлэх биш,
нөгөө модулиасаа `index.ts`-ээр нь асуух нь зөв засвар.

### Гадаад системүүд

QPay, е-баримтын PosAPI, SMS gateway гурвуулаа `src/ports.ts`-ийн ард. Шалтгаан
нь хийсвэрлэл биш — эдгээр унадаг, доройтлын шатлалыг зөвхөн захиалгаараа
унагааж чаддаг үед л тестлэх боломжтой. `FakeTaxProvider.down = true` гэж
тавиад захиалга ажилласаар байгааг шалгадаг тест бий.

### Гурван хамгаалалт схем дээр суусан

| Хязгаарлалт | Юунаас хамгаалдаг |
|---|---|
| `table_hold` EXCLUDE (gist) | Нэг ширээг хоёр зочинд амлах |
| `fire_job_one_pending_idx` | Нэг захиалгыг хоёр удаа галлах |
| `payment (provider, provider_ref)` | Callback давхардаж хоёр удаа тооцогдох |
| `ledger.entry_balanced` (trigger) | Нэг талдаа бичигдсэн гүйлгээ |
| `ledger.transfer.idempotency_key` | Хоёр товшилт хоёр удаа төлөх |

Кодыг алдаж болно, хязгаарлалтыг алдахгүй.

### Түрийвч

Хаана ч `balance` багана байхгүй. Үлдэгдэл гэдэг нь тухайн дансны бичилтүүдийн
`SUM(amount_mnt)` — унасан хүсэлт хагас шинэчилж чадахгүй, тайлбарлаж буй
бичилтүүдээсээ хазайхгүй, QPay-тэй бүтцээрээ тулна. Алдааг засах арга нь
эсрэг гүйлгээ бичих — аудит ч яг үүнийг хүлээдэг.

Хоолны төлбөр эхлээд үлдэгдлээс хасагдаж, хүрэлцэхгүй бол **зөрүүг нь л**
провайдераас татдаг: 31 500₮-тэй зочин 18 500₮-ийн хоол захиалахад картын
цонх огт гарахгүй.

## Өдрийн симуляц

```bash
npm run sim                        # анхдагч: 15 ресторан × 40 захиалга
npm run sim -- --slot-cap 2        # зүсмийн таазны мэдрэмж
npm run sim -- --signal-drop 1     # дохиогүй горим (L1 доройтол)
```

3 цаг 45 минутын үйлчилгээ ~65 мс-д гүйнэ. Тест хатуу нөхцлийг (давхар
галлалт, станцын ачаалал, хууль бус шилжилт) 5 seed ба гурван стресс
тохиргоон дээр шалгадаг.

### Симуляцаас гарсан гурван дүгнэлт

1. **Зүсмийн тааз 5 биш, 2–3.** Спекийн §07 тооцоо max N = 5 гэсэн ч
   симуляц 5 дээр HELD 29%, нарийвчлал 20% болохыг харуулав. 3 дээр HELD
   17%, нарийвчлал 61%. Онбордингийн бодит `prep_time` тоо орох хүртэл 3-аар
   эхлэх нь зөв.
2. **Arm-ын хариу бол системийн тэнхлэг.** T−15-ын «Та замд гарсан уу?»
   хариуг загварчлахад нарийвчлал 22% → 61% үсрэв. Галлах мөчид зочин ихэвчлэн
   гэрээсээ гараагүй байдаг тул физик дохио (geofence) дангаараа хожимддог.
3. **Дохио тасрах хувь шууд гараар галлалт болж хувирдаг.** 30% дохиогүй үед
   гараар галлалт 41%. SMS-ийг үндсэн суваг болгох шийдвэрийн үнэ цэн эндээс
   шууд харагдана.

Одоогийн байдал (seed 20260902, тааз 3): нарийвчлал ±3 мин **61%** (зорилт 85%),
TTFB < 3 мин **71%** (зорилт 60%), HELD **17%** (зорилт 3%). Цаашид хаах зай:
жинхэнэ хэмжсэн `prep_time`, станцын тохиргоо ресторан бүрээр.

## API

```bash
npm run api          # :3000
npm run scheduler    # тусдаа процесс
```

Зочин утасны дугаар + OTP-оор нэвтэрнэ (нууц үг байхгүй). Таблет нэг удаагийн
8 оронтой кодоор холбогдож, урт хугацааны токен авна — ops-оос хэдийд ч
цуцлагдана. Бүх токен hash хэлбэрээр хадгалагдана.

`GET /v1/kds/tickets` нь гурван баганыг нэг дуудлагаар өгдөг. v1-д WebSocket
биш poll: таблет дахин ачаалахад үнэнийг шууд авдаг, replay-ийн цонх буруу
болох эрсдэлгүй. Дуудлага бүр heartbeat болж бүртгэгддэг тул тусдаа ping
хэрэггүй бөгөөд бодит идэвхтэй байдлаас салж чадахгүй.

Алдааны бичвэр `src/api/errors.ts`-д монголоор бэлэн — клиент `message_mn`-ийг
шууд харуулна, орчуулга давхардахгүй.

## Байршуулалт

Ажиллаж байгаа демо: **https://basu.burzai.cloud** (`/` нүүр, `/dine` хоол,
`/kds` тогооч)

```
basu.burzai.cloud → nginx → 127.0.0.1:3210 → basu-api.service
                                             PostgreSQL 16 :5433
```

`BASU_MODE` нь хоёр процессын цагийг тодорхойлно:

| | API | Scheduler |
|---|---|---|
| `demo` | удирдаж болох цаг, `/dev/*` нээлттэй | **ажиллахгүй** — tick нь `/dev/tick`-ээс |
| `production` | системийн цаг, `/dev/*` байхгүй | 1 сек тутам |

Хоёр процесс тус тусдаа демо цаг барьж чадахгүй — салж холдоод, scheduler
үдийн хоолыг хэдэн цагаар эрт галлаад зочдыг no-show гэж бичнэ. Тиймээс демо
горимд scheduler эхлэхээсээ татгалзаж, шалтгаанаа хэлдэг.

**Демо горим `/dev/*`-ыг ил гаргадаг**: цаг удирдах, OTP-гүй нэвтрэх, таблет
холбох. Хаалттай байх шаардлагатай бол `BASU_MODE=production` болгож,
`basu-scheduler`-ыг асаана.

## Демо өгөгдөл

`npm run seed` — Шангри-Ла орчмын **10 ресторан, 60 хоол**. Тодорхойлолт нь
`src/seed/catalogue.ts`-д: хоол бүр `prep` (хийхэд хэдэн минут) ба `hold`
(чанараа алдалгүй хэдэн минут зогсох) хоёртой, ресторан бүр өөр өөр станцын
бүтэцтэй.

Олон янз байдал нь чимэг биш: буузны газар бол удаан уурын шүүгээ, урт hold;
шарлагын газар бол хурдан хоёр зурвас, hold бараг тэг. Төлөвлөгч тэдгээр дээр
**өөр өөрөөр** ажилладаг — бүх ресторан ижил гал тогоотой демо нэг зан төлөвийг
арав дахин үзүүлнэ.

Хоолны зураг `/dishes/<slug>.svg`-ээс зурагдана. Зурсан зураг болохоос гэрэл
зураг биш: бэлэн фото авах гэдэг хэн нэгний хоолыг өөрийнх мэт харуулах, эсвэл
лиценз худалдаж авах. Эдгээр нь ~1 КБ, хэзээ ч 404 өгөхгүй, ресторанны
хийдэггүй хоолыг харуулж чадахгүй. Бодит фото ирвэл `menu_item.image_url`-д
тавихад бусад зүйл өөрчлөгдөхгүй.

### Өчигдрийн хоол

`npm run seed` нь өнгөрсөн өдрийн ~60 захиалга, **50 үнэлгээ** мөн үүсгэнэ
(`src/seed/history.ts`). Арван ресторан бүгд «үнэлгээ алга» гэж бичсэн газрын
зураг нь боломжийн хэлбэрийг харуулна, утгыг нь харуулахгүй.

Эдгээр нь хаагдсан захиалгад холбогдсон бодит үнэлгээ — чөлөөт оноо биш.
Дундаж, сэтгэгдэл, хоол тус бүрийн оноо бүгд production-ы барих яг тэр
өгөгдлөөс тооцоологдоно.

### Демо: бүх гал тогоо нэг дэлгэц дээр

Таблет зөвхөн өөрийн ресторанны тасалбар харна — токен түүнийг заадаг, `/v1`
хэрэгжүүлдэг, тест шалгадаг. Гэвч заавар арван ресторан хооронд явдаг тул
есөн ресторанд өгсөн захиалга арав дахь дээр нь холбогдсон дэлгэцэд огт
харагдахгүй.

Тиймээс `/kds` дээр **«Бүх гал тогоо»** сонголт бий. `/dev/kds/tickets` нь
бүгдийг нэгтгэж, тасалбар бүр дээр ресторанны нэр гарна. `/v1`-ийн
тусгаарлалт хэвээр.

### Демо горимд хамгаалалт унтарна

«Тогооч харахгүй бол захиалга авахгүй» гэсэн дүрэм production-д ажиллана —
хоол хийх хүнгүй байхад мөнгө авах нь системийн хийж болох хамгийн муу зүйл.
Демо горимд унтраалттай: эхний таб ажиллахын тулд хоёр дахийг нээх шаардлагатай
байх нь заавар биш, оньсого болно.

## Үнэлгээ

Хоол гардуулагдсаны дараа зочин **од өгч, сэтгэгдэл үлдээнэ** — ресторанд нэг,
захиалсан хоол тус бүрд нэг.

Хоёр асуулт зориудаар тусдаа:

| | |
|---|---|
| **Од** | Сайхан байсан уу — дараагийн зочны мэдэх ёстой зүйл |
| **«Цагтаа ирсэн үү?»** | Бидний мэдэх ёстой зүйл — бүтээгдэхүүн үүгээр л дүгнэгдэнэ |

Таван одтой боловч арван минут хоцорсон хоол нь нэг хэмжүүрээр амжилт, нөгөөгөөр
бүтэлгүйтэл. Нэг оноо болгон нэгтгэвэл яг тэрийг л нуух болно.

Үнэлгээ нь **захиалгад** харьяалагдана, зочин-ресторан хосод биш: энэ хүн энэ
хоолыг энэ өдөр идсэн гэдгийн баталгаа. Хэн ч бичиж чадах сайт дээрх үнэлгээнээс
илүү үнэ цэнэтэй байх шалтгаан нь тэр.

Хамгаалалт: зөвхөн `SERVED`/`CLOSED` захиалга, зөвхөн эзэн нь, захиалгад
байгаагүй хоолны од хаягдана, утасны дугаар сэтгэгдлийн хажууд хэзээ ч гарахгүй
(нэр эсвэл сүүлийн 4 орон).

## Маршрут

Зочны байршил мэдэгдмэгц ресторан хүртэлх **зам зурагдана** — хэдэн км, хэдэн
минут алхах нь хуудасны дээд талд гарна.

Хотод хоёр цэгийн хоорондох шулуун зай гуравны нэгээр богино худал: барилга
дундуур байдаг. Тиймээс замын геометрийг OSRM-ээс авна.

**Хугацааг нь бид өөрсдөө тооцно.** Нийтийн OSRM демо `/foot/` хүсэлтэд ч
машины профайл хариулдаг — ижил хүсэлт 910м-ийг 87 секундэд гэж хэлдэг нь
37 км/ц, алхалт биш. Геометр ба зай нь замын бодит хэмжээ тул тэдгээрийг авч,
хугацааг зайнаас нь 80 м/мин-ээр гаргана.

Router хүрэхгүй бол шулуун шугам буцаана — клиент түүнийг **тасархай зураасаар**
зурна, таамаг нь хэмжсэн маршрут шиг харагдахгүй. `ROUTER_URL` нь өөрийн OSRM
рүү заах цэг.

## Газрын зураг

Зочны хуудас газрын зургаас эхэлдэг: «таван минутын зайд ямар хоол байна» гэдэг
нь цэсний асуулт болохоосоо өмнө **байрлалын** асуулт. Тэмдэглэгээ дарахад цэс
доороос гарч ирж, тэндээсээ шууд захиална.

Tile нь MapLibre GL + өөрсдийн вектор tile. FuelNet төслийн стилийг хөрвүүлж
авсан — хашааны хил, монгол POI нэр орсон, өнгө ба zoom-ийн эмтрэлт нь
хэн нэгэн аль хэдийн утсан дээр өдрийн гэрэлд харсан стиль.

```
/tiles/{z}/{x}/{y}  →  MAP_TILES_UPSTREAM (анхдагч monzasvar.mn)
/fonts/{stack}/{range}.pbf
```

Прокси болсон шалтгаан нь `src/api/tiles.ts`-д: tile хостын nginx ба Martin
хоёулаа `Access-Control-Allow-Origin` нэмдэг тул браузер толгойг хоёр удаа
хараад хариуг бүхэлд нь татгалздаг. Нэг origin дээр CORS гэж байхгүй.

**Байршлын дохио одоо бодитоор ажиллана.** ETA загвар 800м / 300м зурвасыг
эхнээсээ мэддэг байсан ч ялгаруулах зүйл байгаагүй — хэн ч хаана байгааг
мэдэхгүй байсан. Зочин зурвас давахад нэг удаа мэдэгдэж, төлөвлөгч гал тавих
цагийг зөөнө.

## Браузерыг асуух

```bash
npm run probe:route                          # захиалга → маршрут, бүтнээр
npm run probe:route -- https://host shot.png
```

Бодит байршил өгсөн Chrome-оор зочны урсгалыг бүтнээр гүйлгэж, маршрут
**гуйгдсан эсэх**, эх сурвалжид **орсон эсэх**, дэлгэц дээр **зурагдсан эсэх**
гурвыг тусад нь хэлнэ. Гурав нь салж байсан: эх сурвалж дүүрэн, дэлгэц хоосон.


```bash
npm run inspect                          # локал зочны хуудас
npm run inspect -- https://host/kds 10   # хаанаас ч, 10 секунд
npm run inspect -- http://localhost:3000/ 8 shot.png
```

Жинхэнэ Chrome ажиллуулж, консолын алдаа, бүтэлгүй хүсэлт, зурагдсан эсэхийг
хэлнэ. Газрын зураг үүнийг зайлшгүй болгосон: tile прокси дээр байт байтаараа
зөв байсан ч браузер **огт гуйгаагүй**, үүнийг curl хэзээ ч харуулахгүй.

Зурагдсан эсэхийг **дэлгэцийн зургаас** тоолно, canvas-аас биш —
`preserveDrawingBuffer`-гүй WebGL контекст буцааж уншихад хоосон гардаг тул
төгс ажиллаж байгаа газрын зураг «нэг өнгө» гэж мэдээлэгддэг.

## Basu бүрхүүл

Basu бол нэг апп, дотроо хэд хэдэн зүйлтэй. `/` бол нүүр дэлгэц: аппуудын
икон, дээр нь зочны **одоо явагдаж байгаа** захиалга. Эхний икон нь энэ
репод бичигдсэн dine-in урьдчилсан захиалга — `/dine`.

Нүүр домэйны логик агуулдаггүй. Аппуудын жагсаалт `src/web/index.html`-ийн
`APPS` массив — хоёр дахь апп нэмнэ гэдэг энд нэг мөр нэмнэ гэсэн үг. Икон нь
inline SVG: launcher өөрийгөө зурахын тулд сүлжээ хүлээдэггүй.

«Идэвхтэй» зурвасыг `GET /v1/orders` тэжээнэ — зочны дуусаагүй захиалгууд,
болох дарааллаараа. Тэр жагсаалтыг серверээс асуудаг болохоор:

- нүүр аль захиалга гэдгийг мэдэлгүйгээр «12:21-д гал» гэж хэлж чадна,
- `/dine` дахин ачаалахад зочин хоосон газрын зураг биш, өөрийн төлөв дээрээ
  буцаж бууна,
- нүүрнээс `?order=…`-аар шууд тухайн захиалга руу орно.

Нүүр өөрөө хэзээ ч сесс үүсгэдэггүй: нэвтрэх нь dine-in аппын хэрэг, зүгээр
нэг нээж үзсэн хүнд данс нээж өгөх нь тэр зочилтын үнийг худал хэлж байгаа
хэрэг.

## iOS апп

`ios/` — SwiftUI, гуравдагч сан ашиглаагүй. Вэб хуудсууд хэвээрээ: демо,
тогоочийн дэлгэц, батлах тест тэндээ. Утасны апп бол өөр нэг клиент, өөр
сервер биш — яг тэр `/v1`-ийг дуудна.

```bash
brew install xcodegen        # нэг удаа
npm run dev                  # API :3000 дээр байх ёстой
npm run ios                  # төсөл үүсгэх → build → симулятор дээр ажиллуулах
npm run ios:test             # нэгжийн + бүтэн урсгалын тест
```

Сервер унтраалттай үед апп хоосон харагдахаа больж, **«Серверт холбогдож
чадсангүй»** гэж хэлээд «Дахин» товч гаргана — debug build дээр ямар хаяг руу
ярьж байгаагаа хамт бичнэ. Хоосон газрын зураг ба холбогдоогүй сервер хоёр
дэлгэцэн дээр адилхан харагддаг ч, хийх зүйл нь тэс өөр.

`.xcodeproj` git-д байхгүй. Эх нь `ios/project.yml`, төслийг `xcodegen`
секундэд үүсгэдэг — файл нэмэх бүрд өөрчлөгддөг, merge-д муу байдаг
generated файлыг хадгалах шалтгаан алга.

```
ios/Basu/
  App/          Оролт, навигаци, демо цагийн зурвас
  Core/         API клиент, моделууд, сесс (Keychain), байршил, формат
  Design/       app.css-ийн өнгө, chip, товч — хоёр газарт нэг бүтээгдэхүүн
  Home/         Basu нүүр: иконы сүлжээ + идэвхтэй захиалга
  Dine/         Газрын зураг, цэс, төлөв, үнэлгээ, хоолны зураг
```

Гурван шийдвэр тайлбартай:

**Токен Keychain-д.** Энэ бол хэн нэгний өдрийн хоолны мөнгөнд хүрэх эрх;
`UserDefaults` бол backup бүр задлан авч явдаг plist.

**Хоолны зургийг апп өөрөө зурна.** SwiftUI SVG уншдаггүй, харин хоёр дахь
хувь өнгөний хүснэгтийг апп дотор хадгалбал сервер дээр өнгө солиход утсанд
хуучнаараа үлдэнэ. Тиймээс `GET /v1/dishes` тоог нь өгч, ес форм тус бүрийг
клиент өөрийн хэлээрээ зурна (`src/api/dishes.ts` ↔ `Dine/DishArt.swift`).

**Идэмпотентын түлхүүр «төлөх» товчны нэг даралтад харьяалагдана.** Сагснаас
гаргаж авсан түлхүүр маргааш ч мөн адил байх тул цуцлаад дахин захиалсан
зочинд хуучин, цуцлагдсан захиалгыг нь буцааж өгдөг. Нэг оролдлого = нэг
түлхүүр; сүлжээ огт хүрээгүй үед л хадгалагдана.

Байршлыг зөвхөн ашиглаж байх үед асууна. T−15-ын «Та замд гарсан уу?» болон
800/300 метрийн хоёр зурвас нь бүтээгдэхүүний өөрийн хэмжүүр — арын байршил
асуух нь апп-д хэрэгтэйгээс хамаагүй том амлалт болно.

Үсэг: Golos Text/IBM Plex Mono вэб фонтуудыг апп дотор суулгаагүй, системийн
SF Pro / SF Mono-г ашиглана. Өнгө, зай, бүтэц нь адил.

## Интерфейс

`src/web/` — build алхамгүй, энгийн HTML + ES module. PWA-д framework
хэрэггүй бөгөөд харахын тулд эхлээд хөрвүүлэх шаардлагатай интерфейсийг хэн ч
хардаггүй. Загварын систем нь спекийн баримтуудтай нэг — ажиллаж байгаа
бүтээгдэхүүн ба түүнийг үндэслэсэн баримт хоёр нэг зүйл шиг харагдана.

Тогоочийн дэлгэц бол баримт биш **багаж**: хоёр метрээс, нойтон гараар
уншигдана. Тиймээс бүх зүйл вэб апп-аас том, төлөв нь өнгө болон байрлалаар
дамжина — HELD улаан хүрээтэй, хоцорсон нь улбар шар.
